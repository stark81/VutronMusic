# 本地歌单功能实现计划

## 需求摘要

为 VutronMusic 实现本地歌单的创建、重命名、删除、曲目增删与排序功能。基于 SQLite 持久化（`better-sqlite3`），重启后数据不丢失。歌单封面默认取第一首歌曲封面，空歌单使用 `default-cover`。

---

## 结构化需求

### R-1: 歌单 CRUD {status=draft}

用户能够创建、重命名、删除本地歌单。

**验收标准：**
- [ ] 可在本地音乐页创建新歌单，输入名称后确认即创建
- [ ] 可重命名已有歌单（右键菜单或编辑按钮）
- [ ] 可删除歌单，删除前有确认提示
- [ ] 歌单数据写入 SQLite，reload 后仍然存在

### R-2: 曲目增删与排序 {status=draft}

歌单内容支持添加曲目、移除曲目，并持久化保存排序。

**验收标准：**
- [ ] 可向歌单添加一首或多首本地曲目（从曲目列表多选添加）
- [ ] 可从歌单中移除曲目
- [ ] 歌单内曲目顺序可拖拽调整，排序结果落盘持久化
- [ ] 刷新或重启后曲目顺序不变

### R-3: 歌单封面逻辑 {status=draft}

歌单封面默认取第一首歌曲的封面；若歌单为空则使用 `default-cover`。

**验收标准：**
- [ ] 歌单包含曲目时，封面显示第一首曲目的 `picUrl`
- [ ] 歌单为空时，封面显示 `default-cover`（即 `src/public/images/default.jpg`）
- [ ] 曲目增删导致第一首变化时封面自动更新

## 数据库设计

### 新增表：LocalPlaylist

```sql
CREATE TABLE IF NOT EXISTS LocalPlaylist (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    sortOrder INTEGER NOT NULL DEFAULT 0,
    coverUrl TEXT,
    createTime INTEGER NOT NULL,
    updateTime INTEGER NOT NULL
);
```

### 新增表：LocalPlaylistEntry

```sql
CREATE TABLE IF NOT EXISTS LocalPlaylistEntry (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    playlistId INTEGER NOT NULL,
    trackId TEXT NOT NULL,
    pluginId TEXT NOT NULL,
    sourceContext TEXT NOT NULL DEFAULT '{}',
    position INTEGER NOT NULL DEFAULT 0,
    createTime INTEGER NOT NULL,
    FOREIGN KEY(playlistId) REFERENCES LocalPlaylist(id) ON DELETE CASCADE,
    FOREIGN KEY(trackId) REFERENCES Track(id)
);
CREATE INDEX IF NOT EXISTS idx_playlist_entry_playlist_pos
    ON LocalPlaylistEntry(playlistId, position);
```

### DDL 注入方式

在 `src/public/migrations/plugin.sql` 的 `COMMIT;` 前追加上述两条 `CREATE TABLE IF NOT EXISTS` 语句，不新建迁移文件（遵循项目当前幂等初始化策略）。

### Tables 枚举更新

在 `src/main/db.ts` 的 `Tables` 枚举中添加：

```ts
LocalPlaylist = 'LocalPlaylist',
LocalPlaylistEntry = 'LocalPlaylistEntry'
```

## 实现步骤

### 阶段 1：数据层（DDL + dbHelpers）

**步骤 1.1：添加数据库表定义**
- 在 `src/public/migrations/plugin.sql` 的 `COMMIT;` 前追加 `LocalPlaylist` 和 `LocalPlaylistEntry` 建表语句
- 在 `src/main/db.ts` 的 `Tables` 枚举中添加两个新成员
- (covers: R-1, R-2)

**步骤 1.2：实现 dbHelpers 层 CRUD 函数**
- 在 `src/main/dbHelpers.ts` 中添加以下导出函数：
  - `createLocalPlaylist(name: string): number` — 插入 LocalPlaylist，返回自增 id
  - `renameLocalPlaylist(id: number, name: string): void`
  - `deleteLocalPlaylist(id: number): void` — 先删 entries 再删 playlist（事务）
  - `getAllLocalPlaylists(): LocalPlaylist[]` — 按 sortOrder 排序
  - `getLocalPlaylistDetail(id: number): { playlist, entries }` — 联查 playlist + entries（按 position 排序）
  - `addTracksToLocalPlaylist(playlistId: number, tracks: { trackId, pluginId, sourceContext }[]): void` — 批量插入 entry，position 接在已有最大 position 之后
  - `removeTrackFromLocalPlaylist(playlistId: number, entryId: number): void`
  - `reorderLocalPlaylistTracks(playlistId: number, orderedEntryIds: number[]): void` — 事务内逐条更新 position
  - `updateLocalPlaylistCover(playlistId: number): void` — 查第一首 track 的 picUrl 写入 coverUrl，无条目时写空串
- 每个函数使用 `db.sqlite.prepare(...)` 风格，与现有 `dbHelpers.ts` 一致
- (covers: R-1, R-2, R-3)

### 阶段 2：IPC 通道

**步骤 2.1：注册 IPC handlers**

在 `src/main/IPCs.ts` 的 `initOtherIpcMain` 或单独位置添加以下 `ipcMain.handle`：

| channel | 参数 | 返回 | 说明 |
|---|---|---|---|
| `createLocalPlaylist` | `{ name: string }` | `{ id: number }` | 创建歌单 |
| `renameLocalPlaylist` | `{ id: number, name: string }` | `boolean` | 重命名 |
| `deleteLocalPlaylist` | `{ id: number }` | `boolean` | 删除歌单（替换当前 stub） |
| `getLocalPlaylists` | 无 | `LocalPlaylist[]` | 获取全部本地歌单列表 |
| `getLocalPlaylistDetail` | `{ id: number }` | `{ playlist, entries }` | 获取歌单详情+曲目 |
| `addTracksToLocalPlaylist` | `{ playlistId, tracks }` | `boolean` | 添加曲目到歌单 |
| `removeTrackFromLocalPlaylist` | `{ playlistId, entryId }` | `boolean` | 从歌单移除曲目 |
| `reorderLocalPlaylistTracks` | `{ playlistId, orderedEntryIds }` | `boolean` | 重排曲目顺序 |

- 所有 handler 调用步骤 1.2 中的 dbHelpers 函数
- `deleteLocalPlaylist` 替换当前 `IPCs.ts` 中返回 `false` 的 stub handler
- `upsertLocalPlaylist` 和 `updateLocalPlaylist` 的现存 stub 保留（它们语义不同，供未来兼容）
- (covers: R-1, R-2, R-3)

**步骤 2.2：更新 preload 白名单**

```

│  LocalMusic.vue / PlaylistPage.vue                         │
│    │  window.mainApi.invoke('getLocalPlaylists')            │
│    │  window.mainApi.invoke('createLocalPlaylist', {name})  │
│    ▼                                                       │
│  pluginMusic store (localPlaylists ref, actions)           │
└────────────────────────────────────────────────────────────┘
                         │ IPC (invoke/handle)
                         ▼
┌─ Main Process ─────────────────────────────────────────────┐
│  IPCs.ts handler                                           │
│    │  dbHelpers.createLocalPlaylist(name)                   │
│    ▼                                                       │
│  dbHelpers.ts  (SQL via better-sqlite3)                    │
│    │  INSERT INTO LocalPlaylist ...                         │
│    ▼                                                       │
│  SQLite DB (vutron_music.sqlite)                           │
│    LocalPlaylist / LocalPlaylistEntry 表                    │
└────────────────────────────────────────────────────────────┘
```

## 风险评估（Pre-mortem）

### 🐅 Tigers（真实风险）

| # | 风险 | 严重度 | 分类 | 缓解措施 |
|---|------|--------|------|----------|
| T1 | PlaylistPage.vue 当前只处理 `Playlist`/`likedSongs` 路由，`localPlaylist` 分支可能破坏现有路由逻辑 | **Launch-Blocking** | 先用 `if/else if` 精确匹配路由名，不改动现有分支；先写最小 PoC 验证路由切换 |
| T2 | `sourceContext` 是插件私有 JSON，本地歌单 entry 存储 `sourceContext` 时若 track 被删除则无法还原 | **Fast-Follow** | 同时存储 `trackId` + `pluginId`，可在 Track 表反查基本信息；无法还原的条目标记为"已失效"而非崩溃 |
| T3 | `updateLocalPlaylistCover` 在每次增删曲目时触发，若歌单有大量曲目时可能有性能问题 | **Track** | 只查第一首（`LIMIT 1`），查询极轻量；先不做缓存，监控后决定 |

### 📄 Paper Tigers（他人担心、我方不担心）

| # | 风险 | 回应 |
|---|------|------|
| P1 | 本地歌单和在线歌单在同一个 PlaylistPage.vue 中共存会混乱 | 现有架构已按 `playlistType` 区分渲染分支（`library`/`stream`），加 `local` 是自然扩展 |
| P2 | 不使用 Pinia persist 插件是否会导致数据丢失 | 歌单数据全程走 SQLite（主进程），渲染层 store 只是缓存，重启后从 DB 恢复 |

### 🐘 Elephants（不确定性）

| # | 问题 | 调查方向 |
|---|------|----------|
| E1 | `getLocalMusic` IPC 返回的 `playlists` 数据目前是空数组，现有代码中是否有消费方？ | 检查 `LocalMusic.vue` 中 `playlists['local']?.data?.length` 的使用方式，确认直接替换为真实数据不会破坏现有展示 |

## 排序与优先级

| 阶段 | 内容 | MoSCoW | ICE 评分 |
|------|------|--------|----------|
| 阶段 1 | 数据层（DDL + dbHelpers） | **Must** | 基础依赖，无此后续无法进行 |
| 阶段 2 | IPC 通道 + preload | **Must** | 连接前后端的关键桥梁 |
| 阶段 3 | 类型定义 | **Must** | 编译通过的前提 |
| 阶段 4 | Store 层 | **Must** | UI 所需的状态管理 |
| 阶段 5.2-5.3 | 歌单列表 + 创建 | **Must** | 最高用户可见价值 |
| 阶段 5.1 | PlaylistPage 适配 | **Must** | 查看歌单内容的入口 |
| 阶段 5.5-5.6 | 曲目增删 + 拖拽排序 | **Should** | 核心交互，但可先做静态查看 |
| 阶段 5.4 | 歌单编辑 | **Should** | 重命名是常用操作 |
| 阶段 5.7 | 封面逻辑 | **Could** | 体验优化，不影响功能可用 |
| 阶段 6 | 测试 | **Should** | 保证质量 |

**首版 MoSCoW：**
- **Must**：阶段 1-4 + 阶段 5.1-5.3（歌单 CRUD + 查看）
- **Should**：阶段 5.4-5.6 + 阶段 6（编辑 + 曲目管理 + 测试）
- **Could**：阶段 5.7（封面自动更新）
