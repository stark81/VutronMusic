# 文档重组计划

## 目标

将三个版本的文档优势合并：
- **版本 A** 的强 AI 编程支持（约束规则、决策优先级、不可违反规则）
- **版本 C** 的强产品叙事（为什么这样设计、用户视角的解释）
- **版本 B** 的清晰目录结构

## 核心原则

1. **单一信息源**：每个概念只在一个地方定义，其他地方引用
2. **受众分离**：AI 编程规则在根目录文件，人类可读文档在 VitePress
3. **文件有界**：每个文件 ≤150 行（ADR 和 schema SQL 除外）
4. **无叙事冗余**：产品文档讲"为什么"，技术文档讲"怎么做"，不重复

- `dev/` 目录删除：modification-guide 的"新增插件/IPC/Store"等模式移入 `plugin/getting-started.md`，debugging 的关键日志路径移入 `architecture/overview.md`，plugin-dev-reference 与 `plugin/api.md` 合并
