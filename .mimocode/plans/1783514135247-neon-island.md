# 重构 playlistSource：支持聚合播放列表的多插件来源信息

## 问题分析

### 当前结构

```typescript
// src/types/music.d.ts:201-205
export type PlaylistSourceInfo = {
  type: SourceType
  plugin: PluginId | 'all'
  sourceContext: Record<string, any>  // 单个来源上下文
}
```

### 核心问题

当播放聚合类型的播放列表（如跨网易云+酷狗的"我喜欢的音乐"）时，`sourceContext` **只存储了一个插件的来源上下文**。具体流程：

1. `PlaylistPage.vue:338` 中 `loadLikedData` 设置：
   ```typescript
   playlist.value.sourceContext = { id: type, trackIds: [], loadedIDs: [] }
   ```
   `id` 被设为服务类型字符串（如 `'library'`），而非具体歌单 ID

2. `PlaylistPage.vue:400` 中 `play()` 将此 context 传给 `replacePlaylist`：
   ```typescript
   sourceContext: { ...playlist.value.sourceContext, pluginType: pluginType.value }
   ```

3. `player.ts:421` 中 `reportPlayback` 发送：
   ```typescript
   sourceCtx: { ...playlistSource.value, plugin: track.pluginId }
   ```

4. `netease.js:1821` 中 scrobble 读取：
   ```typescript
   const sourceid = sourceCtx.sourceContext?.id  // 得到 'library' 而非真实歌单 ID
   ```

### 影响范围

| 位置 | 文件 | 影响 |
|------|------|------|
| scrobble 打卡 | `netease.js:1817-1827` | `sourceid` 为 `'library'`，打卡无法关联到真实歌单 |
| "返回歌单" 导航 | `player.ts:112-141` (`getListSourcePath`) | 依赖 `sourceContext.id` 判断路由，当前能工作但语义不精确 |
| 滚动到当前歌曲 | `VirtualTrackList.vue:292-293` | 依赖 `sourceContext.id` 比较，聚合时可能错误匹配 |
| reportPlayback 广播 | `IPCs.ts:1855` | 使用 `sourceCtx.plugin`（已被覆盖为 track.pluginId），无直接问题 |

### 关键观察

- `playList.value` 的结构是 `[PluginId, Record<string, any>][]`，每个 track 已携带自己的 `pluginId` 和 `sourceContext`
- `pluginMusicStore.likedTracks` 中已按插件分别存储了各自的 `sourceContext`（如网易云的 `{ id: 歌单ID, trackIds, loadedIDs }`）
- 问题根源在于：**聚合播放列表的全局 sourceContext 丢失了各插件的独立上下文**

---

## 修改方案

### 方案：新增 `pluginSourceContexts` 字段

在 `PlaylistSourceInfo` 中新增一个按插件 ID 索引的来源上下文映射，保留原有 `sourceContext` 作为主上下文（向后兼容）。

### 1. 修改类型定义

**文件**: `src/types/music.d.ts:201-205`

```typescript
export type PlaylistSourceInfo = {
  type: SourceType
  plugin: PluginId | 'all'
  sourceContext: Record<string, any>
  pluginSourceContexts?: Record<PluginId, Record<string, any>>
}
```

`pluginSourceContexts` 为可选字段：
- 聚合播放列表（`plugin === 'all'`）时，存储各插件的独立来源上下文
- 单插件播放列表时，可省略或只存一项

### 2. 修改 Player Store

**文件**: `src/renderer/store/player.ts`

- **line 101-105**: 初始值增加 `pluginSourceContexts: {}`
- **line 367-389** (`replacePlaylist`): 参数类型增加可选的 `pluginSourceContexts`
- **line 421** (`reportPlayback`): 改用当前 track 的 pluginId 从 `pluginSourceContexts` 中查找对应上下文

```typescript
// reportPlayback 改动
const trackPluginId = track.pluginId
const trackSourceCtx = playlistSource.value.pluginSourceContexts?.[trackPluginId]
  ?? playlistSource.value.sourceContext
sourceCtx: {
  ...playlistSource.value,
  plugin: trackPluginId,
  sourceContext: trackSourceCtx
}
```

### 3. 修改 PlaylistPage.vue

**文件**: `src/renderer/views/PlaylistPage.vue`

- **line 332-339** (`loadLikedData`): 收集所有插件的 sourceContext

```typescript
const loadLikedData = (plugins: PluginId[]) => {
  const likedTracks = pluginMusicStore.likedTracks
  tracks.value = plugins.map((item) => likedTracks[item]?.data || []).flat()
  tricklingProgress.done()
  show.value = true
  const type = services.value.find((item) => item.code === plugins[0])!.type
  playlist.value.sourceContext = { id: type, trackIds: [], loadedIDs: [] }

  // 新增：收集各插件的独立来源上下文
  const pluginSourceContexts: Record<string, Record<string, any>> = {}
  for (const p of plugins) {
    if (likedTracks[p]?.sourceContext) {
      pluginSourceContexts[p] = likedTracks[p].sourceContext
    }
  }
  playlist.value.pluginSourceContexts = pluginSourceContexts
}
```

- **line 396-408** (`play`): 传递 `pluginSourceContexts`

```typescript
const play = () => {
  const source: PlaylistSourceInfo = {
    type: 'Playlist',
    plugin: pluginId.value,
    sourceContext: { ...playlist.value.sourceContext, pluginType: pluginType.value },
    pluginSourceContexts: playlist.value.pluginSourceContexts
  }
  // ... 其余不变
}
```

### 4. 修改 VirtualTrackList.vue

**文件**: `src/renderer/components/VirtualTrackList.vue`

const showScrollTo = computed(() => {
