# 歌词系统设计

## 歌词获取策略

一首歌可能有多个插件能提供歌词。选择策略：

```
查询本地缓存 → 无缓存 → 遍历已启用插件的 getLyric
  → 先查 TrackSource 关联的插件 → 再查其他插件
  → 第一个成功返回的歌词 → 写入缓存
```

**为什么先返回先得？** 歌词获取是播放路径上的关键步骤，延迟直接影响体验。歌词质量不好时用户可以通过偏移调节补偿。

## 格式支持

支持 LRC、Lyricify 逐字、LDDC 三种格式。

**为什么都支持？** 用户已有 `.lrc` 文件不能要求重新下载；从 Lyricify 导入的应该直接兼容；LDDC 是 Lyricify 生态的扩展。结论：**让 App 兼容已有格式，不要求用户转换。**

## 歌词偏移

歌曲级偏移，持久化到数据库。0.5 秒步进。

**为什么歌曲级而不是全局？** 一首歌不准不应影响所有歌。持久化确保下次播放同一首歌时自动加载。

## 歌词索引更新

不用 `requestAnimationFrame` 轮询，而是用 `setTimeout` 精确预约到下一行的起始时间：

```
计算到下一行的剩余时间 driftTime
→ setTimeout(driftTime * 1000 / playbackRate)
→ 定时器触发时更新 currentIndex
```

**为什么不用 rAF？** rAF 每帧执行（~16ms），大部分时间在做无用功。setTimeout 只在需要切换时触发，CPU 占用极低。
