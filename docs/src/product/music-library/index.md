# 本地音乐库

## 用户场景

本地音乐是 VutronMusic 最基础的音乐来源。用户可能有成百上千的本地音乐文件（FLAC/MP3/WAV 等），需要一套高效的扫描、管理、清理方案。

## 核心流程

```
用户选择本地目录
  │
  ├─ 1. fast-glob 扫描音频文件
  ├─ 2. 与已有记录比对，筛选新文件
  ├─ 3. scanMusic Worker 解析元数据
  │    ├─ 文件标签（标题、艺术家、专辑）
  │    ├─ 时长、码率
  │    ├─ ReplayGain 信息
  │    └─ 封面图片
  ├─ 4. 按去重规则写入数据库
  │    ├─ 新 Artist → 创建
  │    ├─ 新 Album  → 创建
  │    ├─ 新 Track  → 创建（强信号归并）
  │    └─ Audio     → 创建
  └─ 5. 通知渲染进程完成
```

## 用户关心的点

| 关注点       | VutronMusic 的做法                             |
| ------------ | ---------------------------------------------- |
| 扫描速度     | 使用 worker 线程池 + fast-glob，5 万首约数十秒 |
| 匹配准确     | 三级去重策略，保留括注区分不同版本             |
| 元数据完整   | 自动匹配在线平台补充歌词和封面                 |
| 多版本共存   | 同一首歌的不同格式/音质版本自动归并            |
| 文件变动处理 | 重新扫描增量更新，删除的文件标记清理           |

## 去重策略

| 信号强度 | 判断条件                                        | 处理方式                        |
| -------- | ----------------------------------------------- | ------------------------------- |
| 强       | 文件标签内嵌 MusicBrainz Track ID 一致          | 自动归并为同一 Track 的新 Audio |
| 中       | 归一化后标题+专辑+艺术家相同，且时长误差 ≤ 2 秒 | 自动归并为同一 Track 的新 Audio |
| 弱       | 仅部分匹配                                      | 不自动归并，作为独立 Track      |

> 📖 技术实现细节见 [Track 数据模型](../../spec/architecture/database/track)

## 文件变更处理

| 操作         | 策略                                                  |
| ------------ | ----------------------------------------------------- |
| **重新扫描** | 全量扫描，`INSERT OR IGNORE` 写入，已存在数据不受影响 |
| **文件变更** | 同一路径内容不同，需手动更新 Audio 记录               |
| **文件删除** | `clearDeletedMusic` 遍历本地文件，清理不存在的记录    |
| **清除全部** | `deleteLocalMusicDB` 清理所有本地相关记录             |
