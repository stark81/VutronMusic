# 数据清理

> 本地音乐库整体设计见 [index.md](./index.md)。

## 用户场景

随着使用时间的增长，本地音乐库和数据库中会积累各种「不再需要」的数据。数据清理解决的核心问题是：**如何在不影响用户体验的前提下，回收存储空间**。

## 清理分类

```
用户发起的操作
  ├─ 手动清理缓存
  │   ├─ 音频缓存（cacheWorker）
  │   └─ 封面缓存（cover_cache）
  │
  ├─ 插件管理
  │   ├─ 卸载插件 → 清理关联数据
  │   └─ 禁用插件 → 保留数据，可恢复
  │
  └─ 数据管理
      ├─ 清理软删除记录
      └─ 重建索引

系统自动执行
  ├─ 文件删除检测（扫描时自动触发）
  │   ├─ 扫描发现文件不在了
  │   ├─ 标记对应 Audio 为 deleted
  │   └─ 用户可在界面上确认后物理删除
  │
  └─ 缓存 LRU 淘汰（未来规划）
      ├─ 跟踪播放次数和时间
      └─ 空间不足时自动清理最久未访问的缓存
```

## 用户控制

| 操作         | 入口            | 说明                              |
| ------------ | --------------- | --------------------------------- |
| 清理音频缓存 | 设置 → 缓存管理 | 删除所有下载的在线音频缓存        |
| 清理封面缓存 | 设置 → 缓存管理 | 删除所有封面图片缓存              |
| 清理无效数据 | 设置 → 数据管理 | 删除不再引用的 Artist/Album/Track |
| 重建搜索索引 | 设置 → 数据管理 | 重新建立全文搜索索引（未来）      |
| 卸载插件     | 设置 → 插件管理 | 删除插件文件和关联数据            |

> ⚠️ **当前状态**：基础的清理功能可用（清理缓存、清除删除记录）。完全自动化的 LRU 缓存淘汰和插件卸载数据回收尚未实现。

## 思考：清理策略中的权衡

| 权衡               | VutronMusic 的选择         | 理由                                         |
| ------------------ | -------------------------- | -------------------------------------------- |
| 自动 vs 手动       | **用户触发为主，自动为辅** | 音乐数据是用户资产，不应在不告知的情况下删除 |
| 软删除 vs 物理删除 | **先软删，确认后再物理删** | 防止误操作导致数据丢失                       |
| 清理粒度           | **按类别细化**             | 用户可以只清理缓存不动数据库                 |
| 扫描时清理时机     | **在扫描完成后提示用户**   | 不打断扫描流程，用户自行决定                 |
