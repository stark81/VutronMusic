# 从 3.x 升级到 4.0

4.0 把内置音源重构为**插件化架构**，数据模型也随之重写（`Track` / `TrackSource` / `Audio` 三表分离）。旧版本存的登录态、播放器状态、本地音乐索引都不是新格式，**不会自动迁移**，所以升级后看起来「什么都没了」是预期行为，重新登录 + 重新扫描即可恢复。

## 升级后要做的事

| # | 做什么 | 入口 |
| --- | --- | --- |
| 1 | 重新登录各平台（网易云 / 酷狗 / Emby / Jellyfin / Navidrome） | 设置 → 音乐设置 → 插件管理 → 点插件卡片上的「登录」 |
| 2 | 重新选择本地音乐目录并扫描 | 设置 → 音乐设置 → 本地音乐 → 选择目录 |
| 3 | ~~重置播放器状态~~ **已自动化** | 升级后第一次启动会自动重置（见下）；仍异常时手动点一次：设置 → 音乐设置 → 播放器设置 → 重置播放器状态 |

> 播放器状态重置会自动完成：启动时读取上次运行的版本号，低于 4.0.0 就调用一次「重置播放器状态」，并弹提示、记录当前版本。之后正常升级不会再动你的播放列表和音量。

> 4.0 的登录入口在「设置 → 音乐设置 → 插件管理」里，插件卡片上有明显的「登录 / 已登录」按钮；没有已登录插件时卡片会自动展开。也可以直接打开 <code>设置</code> 后跳到登录页：`#/login/netease/QrCode`。

## 常见现象

### 打开软件后歌单/列表全是空的

**原因**：新版本的登录态存在独立数据库里，从 3.x 升级后是空的。

**解决**：按上表第 1 条重新登录；网易云登录后会自动加载歌单。若列表仍为空，看日志里是否有 `UNAUTHORIZED`（账号掉登录）。

### Cookie 登录点了没反应

**原因（4.0.0）**：Cookie 表单的返回值缺少字段时会被校验拦下，登录结果被静默丢弃。

**解决**：升级到修复后的版本；无效 Cookie 现在会显示「Cookie 无效或已过期」。也可以直接用二维码登录替代。

### 本地音乐数量比 Emby 少

**原因**：

1. 4.0.0 有一个历史 bug：匹配在线音源时会把本地歌曲的「本地来源」和歌手关联删掉，这些歌不会出现在本地列表里（已修复，重新扫描一次即可补回）；
2. 本地扫描按扩展名识别音频，Emby 按文件内容嗅探。扩展名不是常见音频格式的文件（例如被改成 `.test` 的 WAV）不会被扫到，改名回正确扩展名即可；
3. 支持的扩展名：`mp3 / aiff / aif / aifc / flac / alac / m4a / aac / wav / opus`。
