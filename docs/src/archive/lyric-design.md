# 歌词格式选型历史

## 格式选型的时间线

```
LRC 格式（1996）
  │ 优势：简单、通用、几乎所有播放器都支持
  │ 局限：无逐字时间戳，不能实现卡拉 OK 效果
  ▼

Lyricify 格式（2016+）
  │ 优势：在 LRC 基础上增加逐字时间戳
  │ 局限：社区标准，非官方格式
  ▼

LDDC 格式
  │ 优势：Lyricify 生态的扩展，逐字歌词更规范
  │ 局限：用户量小，工具链少
  ▼

VutronMusic 的选择：
  ├─ 支持所有三种格式
  └─ 统一解析为标准结构
```

### 为什么都支持？

**决策逻辑**：用户已经有了什么格式的歌词文件？

- 如果用户有 `.lrc` → 不能让他重新下载
- 如果用户从 Lyricify 导入 → 应该直接兼容
- 如果用户用 LDDC 下载 → 应该能读

结论：**不要求用户转换格式，而是让 App 兼容已有格式**。

### 歌词获取策略

```
播放歌曲 → 尝试获取歌词
  │
  ├─ 1. 检查 Lyrics 表（缓存）
  │   ├─ 有 → 直接使用
  │   └─ 无 → 进入下一步
  │
  ├─ 2. 如果 Track 有本地文件
  │   ├─ 尝试读取内嵌歌词
  │   ├─ 尝试读取同路径 .lrc 文件
  │   └─ 有 → 缓存到 Lyrics 表并返回
  │
  ├─ 3. 遍历所有插件的 getLyric 方法
  │   ├─ Promise.any：取第一个成功返回的
  │   └─ 有 → 缓存到 Lyrics 表并返回
  │
  └─ 4. 全部失败 → 标记为「无歌词」
```

## 技术参考

### 歌词解析

所有歌词格式统一解析为：

```typescript
interface ParsedLyric {
  lines: Array<{
    time: number // 毫秒
    text: string
    wordByWord?: Array<{
      // 逐字歌词（可选）
      word: string
      startTime: number
      endTime: number
    }>
  }>
  isWordByWord: boolean // 是否为逐字歌词
}
```

### 数据库

| 表             | 作用                       |
| -------------- | -------------------------- |
| `Lyrics`       | 歌词缓存（每插件独立存储） |
| `LyricOffsets` | 用户微调的歌词偏移量       |

### 歌词显示模式

| 模式 | 说明                       | 使用场景         |
| ---- | -------------------------- | ---------------- |
| 单行 | 仅显示当前行               | 桌面歌词小模式   |
| 双行 | 显示当前行 + 上一行/下一行 | 桌面歌词大模式   |
| 滚动 | 显示前后多行               | 播放器全屏歌词页 |
| 垂直 | 歌词垂直排列               | 桌面歌词垂直模式 |
